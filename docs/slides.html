Design Report Summary

Insurance Claims
Review Agent

A policy-grounded agentic system for medical claims adjudication

What the Agent Does

Two inputs: structured claim data + unstructured policy text

  • Interprets the claim's current state, then consults the relevant policy to validate coverage.
  • Decides the next action from a fixed workflow and a closed, six-action set.
  • Returns a decision with a grounded, per-assertion rationale — never free-text reasoning alone.
  • Deterministic checks run first; the LLM runs only when policy interpretation needs judgment.
  • Unsafe or unresolved cases are routed to human review, never guessed.
MVP: Claude Agent SDK + Sonnet, one schema-constrained tool call per claim (submit_claim_decision), across 3 insurers with synthetic test claims.

Deterministic Overrides Come First

Four gates, evaluated independently, never seen by the model

ConditionAction when it fires alone
Member inactive at date of serviceDeny
Claimed amount above the auto-review threshold ($5,000)Route to senior review
Diagnosis / procedure code inconsistencyRoute to coding review
Missing essential documentation for the claim typeRequest the missing document(s)
2+ overrides firing together → escalate to a senior reviewer. The collision itself is the signal — the MVP does not rank or prioritize between them.

A Closed, Six-Action Set

The model proposes one action via tool calling; application code validates it deterministically


approve_pre_authorization()
approve_claim_payment(payment_in_dollars: float)
deny_claim()
request_missing_documentation(documents: list[str])
route_to_senior_reviewer()
route_to_coding_review()
Grounding check: every rationale assertion needs a valid evidence pointer (policy section or claim field). One correction retry is allowed — if still ungrounded, the decision is discarded and escalated, not degraded and kept.

Every Decision, One Shared Schema

  • decision — enum of the 6 actions, never free text
  • rationale[] — one evidence pointer per factual assertion (policy section or claim field), never inferred or paraphrased
  • confidence — self-reported by the model, not independently verified; treated as a lever, not a metric
  • token_usage — real tokens + cost per call, summed across retries
  • Fixed, non-model-generated disclaimer on every response
Autonomy gate (production design): one more check after validation, keyed per action type — decides auto-execute vs. human sign-off. approve_claim_payment could be cleared for auto-execution while deny_claim stays fully human-gated by policy.

Shadow Mode: Safe Promotion Path

flowchart TB
  EVT["Live claim event"] --> CUR["Currently-deployed agent"]
  EVT --> CAND["Candidate agent (new prompt/model)"]
  CUR --> EXEC["Executes, writes back"]
  CAND --> LOG["Logged only, never executed"]
  LOG --> SAMPLE["Sampled vs. human/SME outcome"]
  SAMPLE --> AGREE{"Agreement clears bar?"}
  AGREE -->|no| HOLD["Hold candidate, feed into failure analysis"]
  AGREE -->|yes, sustained| PROMOTE["Promote, per action type"]
  • Candidate runs on real traffic but never writes back or executes.
  • Sampled against real executed decisions or SME judgment.
  • Promotion is per action type, not all-or-nothing.
  • Ramps as a canary percentage, with automatic rollback if agreement drops.

3 · Evaluation Framework

Golden Set

19 curated claims covering every claim type, all 4 override conditions and their pairwise collisions, all 3 insurers plus the fail-closed path, and 5 ambiguity types.

CategoryMetric
Decision correctnessexact_match, match_with_alternate, arg_correct
Evidence groundinggrounding_recall, grounding_exhausted rate
RobustnessStratified accuracy/consistency, abstention precision + recall
Grading is deterministic and code-based first; SME review and LLM-as-judge are supplements, only trusted once validated against human assessment.

4 · Escalation & Contradictions

Escalate to a human when…

  • Claim is above the auto-review threshold, or multiple overrides fire together
  • The model can't ground its evidence even after one retry
  • The model itself flags contradictory or insufficient evidence
  • The action type isn't yet promoted past shadow mode, or is policy-gated

Four distinct failure situations

SituationAction
Insufficient evidenceRequest the specific missing item by name
Contradictory evidenceRoute to a human; state the conflict — never guess which source wins
Ambiguous / open policyRoute to a human; state that policy doesn't resolve the case
Conflicting source authorityRoute to a human rather than inventing a precedence rule

Safety & Compliance Boundaries

  • Must avoid: medical advice beyond the policy's own language, invented rules where policy is silent, and treating out-of-scope sections as support.
  • A fixed, non-model-generated disclaimer appears on every response.
  • Clinical documents may require encryption/anonymization; the model runs behind a BAA-covered endpoint.

Key Takeaways

  • Deterministic-first design keeps the LLM's footprint — and audit surface — small.
  • Every decision is schema-constrained, evidence-grounded, and fully traceable.
  • Shadow mode + a per-action-type autonomy gate open a safe path to more autonomy.
  • Evaluation is code-first; human review is reserved for what code genuinely can't catch.
